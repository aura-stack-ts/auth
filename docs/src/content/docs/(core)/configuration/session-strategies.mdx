---
title: Session Strategies
description: Configure how Aura Auth stores and maintains user sessions across requests.
---

The `session` option in [`createAuth`](/docs/api-reference/createAuth#session) configures how Aura Auth stores, validates, and manages sessions across requests.

```ts title="@/lib/auth.ts"
import { createAuth } from "@aura-stack/auth"

export const auth = createAuth({
  oauth: [],
  session: {
    maxAge: 60 * 60 * 24 * 7, // 7 days in seconds
    slidingThreshold: 0.5, // 50% of maxAge
    expirationStrategy: "sliding",
  },
})
```

## `strategy`

The `strategy` property selects the session management strategy.

- **`jwt`**: Uses a JWT to represent the session. Session validation does not require a database lookup, although other application operations may still use a database.
- **`database`**: Stores session records in a database, enabling server-side session management, including session revocation and tracking. This strategy is suitable for applications that need direct control over the session lifecycle.

## `jwt`

The `jwt` option configures the JWT session strategy. Its properties apply only when `session.strategy` is set to `jwt`.

<Callout>
  The `jwt` configuration is ignored when the `database` strategy is selected. See the [database configuration](#database) section
  for options specific to database-backed sessions.
</Callout>

### `mode`

The `mode` property determines how session JWTs are protected.

- **`sealed`** (default): Encrypts and authenticates the token, providing confidentiality and integrity. The payload cannot be read without the appropriate key material or modified without detection.
- **`signed`**: Signs the token to provide integrity and authenticity, but does not encrypt the payload. Anyone holding the token can read its contents. Use this mode when another service needs to inspect the claims and verify the signature.
- **`encrypted`**: Encrypts the token to protect the confidentiality of its payload. Unlike `sealed`, this mode does not provide a separate signature. Use it only when its behavior meets the application's security requirements and compatibility needs.

```ts title="@/lib/auth.ts"
import { createAuth } from "@aura-stack/auth"

export const auth = createAuth({
  oauth: [],
  session: {
    strategy: "jwt",
    jwt: {
      mode: "sealed",
    },
  },
})
```

### `issuer`

The `issuer` property sets the JWT issuer (`iss`) claim. It identifies the entity that issued the token and can be used by token consumers to validate its origin.

```ts title="@/lib/auth.ts"
import { createAuth } from "@aura-stack/auth"

export const auth = createAuth({
  oauth: [],
  session: {
    strategy: "jwt",
    jwt: {
      issuer: "my-app",
    },
  },
})
```

### `audience`

The `audience` property sets the JWT audience (`aud`) claim. It identifies the intended recipient or recipients of the token and can be used to restrict token acceptance to specific applications or services.

```ts title="@/lib/auth.ts"
import { createAuth } from "@aura-stack/auth"

export const auth = createAuth({
  oauth: [],
  session: {
    strategy: "jwt",
    jwt: {
      audience: "my-app-client",
    },
  },
})
```

## `database`

The `database` configuration controls database-backed session management. These options apply only when `session.strategy` is set to `database`.

<Callout>
  The `database` configuration is ignored when the `jwt` strategy is selected. See the [JWT configuration](#jwt) section for
  options specific to JWT-based sessions.
</Callout>

### `deleteStrategy`

The `deleteStrategy` property determines how session records are deleted. It accepts `soft` or `hard` and defaults to `soft`.

- **`soft`**: Marks a session as deleted without physically removing its database record. This can preserve records for auditing or recovery, depending on the adapter's implementation.
- **`hard`**: Permanently removes the session record from the database.

```ts title="@/lib/auth.ts"
import { createAuth } from "@aura-stack/auth"

export const auth = createAuth({
  oauth: [],
  session: {
    strategy: "database",
    deleteStrategy: "soft",
  },
})
```

### `maxSessions`

The `maxSessions` property sets the maximum number of concurrent sessions allowed per user. When the limit is exceeded, the oldest session is invalidated to make room for the new session. The default is `5`.

```ts title="@/lib/auth.ts"
import { createAuth } from "@aura-stack/auth"

export const auth = createAuth({
  oauth: [],
  session: {
    strategy: "database",
    maxSessions: 5,
  },
})
```

### `touchInterval`

The `touchInterval` property sets the minimum interval, in seconds, between updates to a session's last-activity timestamp in the database. This can reduce database writes while maintaining activity information for session management. The default is `300` seconds (5 minutes).

```ts title="@/lib/auth.ts"
import { createAuth } from "@aura-stack/auth"

export const auth = createAuth({
  oauth: [],
  session: {
    strategy: "database",
    touchInterval: 300, // 5 minutes
  },
})
```

## `adapter`

The `adapter` property specifies the database adapter used to persist session data. Aura Auth provides a Prisma adapter through the `@aura-stack/prisma` package.

The adapter must be configured with the application's Prisma client and passed to `createAuth` when using the `database` session strategy.

<Callout>
  An adapter is required when using the `database` strategy. If no adapter is provided, Aura Auth throws an error during
  initialization.
</Callout>

The following example configures the Prisma adapter with PostgreSQL:

```ts title="@/lib/auth.ts"
import { createAuth } from "@aura-stack/auth"
import { PrismaPg } from "@prisma/adapter-pg"
import { prismaAdapter } from "@aura-stack/prisma"
import { PrismaClient } from "@/generated/prisma/client.ts"

const adapterPg = new PrismaPg({
  connectionString: process.env.DATABASE_URL,
})

export const prismaClient = new PrismaClient({
  adapter: adapterPg,
})

export const adapter = prismaAdapter({
  client: prismaClient as any,
  deleteStrategy: "soft",
})

export const auth = createAuth({
  oauth: [],
  session: {
    strategy: "database",
    adapter,
  },
})
```

## `maxAge`

The `maxAge` property specifies the session's maximum age in seconds. Its exact effect depends on the configured expiration strategy. When the session reaches its applicable expiration time, it can no longer be used and the user must authenticate again. The default is 15 days (`60 * 60 * 24 * 15` seconds).

```ts title="@/lib/auth.ts"
import { createAuth } from "@aura-stack/auth"

export const auth = createAuth({
  oauth: [],
  session: {
    maxAge: 60 * 60 * 24 * 7, // 7 days
  },
})
```

## `maxDuration`

The `maxDuration` property sets the maximum absolute lifetime of a session in seconds, regardless of activity. Once this limit is reached, the session expires even if it has been renewed during that period.

```ts title="@/lib/auth.ts"
import { createAuth } from "@aura-stack/auth"

export const auth = createAuth({
  oauth: [],
  session: {
    maxDuration: 60 * 60 * 24 * 30, // 30 days
  },
})
```

## `expirationStrategy`

The `expirationStrategy` property determines how session expiration is calculated and renewed.

- **`fixed`**: The session expires after a fixed duration from its creation time.
- **`rolling`**: The expiration time is renewed as activity occurs.
- **`absolute`**: The session has a fixed expiration time that activity does not extend.
- **`sliding`**: The expiration time is extended according to the sliding-expiration policy, subject to the configured lifetime limits.

```ts title="@/lib/auth.ts"
import { createAuth } from "@aura-stack/auth"

export const auth = createAuth({
  oauth: [],
  session: {
    expirationStrategy: "rolling",
  },
})
```

## `slidingThreshold`

The `slidingThreshold` property sets the fraction of `maxAge` that must elapse before a sliding session's expiration is extended. For example, `0.5` represents 50% of `maxAge`.

```ts title="@/lib/auth.ts"
import { createAuth } from "@aura-stack/auth"

export const auth = createAuth({
  oauth: [],
  session: {
    slidingThreshold: 0.5, // 50% of maxAge
    expirationStrategy: "sliding",
  },
})
```
