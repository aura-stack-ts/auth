title: Identity Schema
description: Configure and extend the identity schema Aura Auth uses to validate user data, across Zod, Valibot, ArkType, and TypeBox.

The `identity` option on [`createAuth`](/docs/api-reference/createAuth#identity) defines the schema Aura Auth uses to validate and shape user identity data. The schema you provide is also used to derive the `User` and `Session` types used across the rest of the library, so setting it up correctly gets you type-safe access to your custom fields everywhere `User`/`Session` are used.

```ts title="@/lib/auth.ts" lineNumbers
import { createAuth } from "@aura-stack/auth"
import { identitySchema, zod } from "@aura-stack/auth/identity/zod"

export const auth = createAuth({
  oauth: [],
  identity: {
    schema: identitySchema,
    unknownKeys: "strip",
    skipValidation: false,
  },
})
```

## `schema`

Zod, Valibot, ArkType, and TypeBox are supported as the first-class and import its default schema from `@aura-stack/auth/identity/:schema`.

Built-in type inference (via `InferUser`/`InferSession`) is supported for Zod, Valibot, and ArkType. TypeBox is supported for validation but does not support direct type inference — see the [Type Inference](#type-inference) section for the workaround.

Each supported validator ships a default `identitySchema` containing the required base fields. Extend it with whatever additional fields your application needs.

<Tabs items={["zod", "valibot", "arktype", "typebox"]} groupId="schema-validation" persist>

<Tab value="zod">

```ts title="@/lib/auth.ts" lineNumbers
import { createAuth } from "@aura-stack/auth"
import { identitySchema, zod } from "@aura-stack/auth/identity/zod"

const schema = identitySchema.extend({
  role: zod.enum(["admin", "user"]),
})

export const auth = createAuth({
  oauth: [],
  identity: {
    schema,
  },
})
```

</Tab>

import { createAuth } from "@aura-stack/auth"

## `unknownKeys`

By default, fields present on an incoming identity object but absent from your schema are silently removed (`strip`). Change this with `unknownKeys` if you need unvalidated passthrough fields, or want unexpected fields to fail loudly during development.

```ts title="@/lib/auth.ts" lineNumbers
import { createAuth } from "@aura-stack/auth"

export const auth = createAuth({
  oauth: [],
  identity: {
    unknownKeys: "strict", // throws if the identity object has fields outside the schema
  },
})
```

## `skipValidation`

When schema validation isn't relevant to your application, set `skipValidation` to `true` to accept any shape of identity object without enforcement.

```ts title="@/lib/auth.ts" lineNumbers
import { createAuth } from "@aura-stack/auth"

export const auth = createAuth({
  oauth: [],
  identity: {
    skipValidation: true,
  },
})
```

<Callout type="warning">
  Skipping validation removes Aura Auth's guarantee that `User`/`Session` objects match your declared shape at runtime. Only
  disable this if your upstream identity provider or database layer already enforces the shape you need.
</Callout>

## Type inference

Aura Auth provides utility types to infer `User` and `Session` from your identity schema, so the rest of your application gets type safety and autocompletion on custom fields without manual duplication.

Infer directly from the `auth` instance with `InferUser`/`InferSession`, or from the schema itself with `UserFrom`/`SessionFrom`.

<Tabs items={["zod", "valibot", "arktype", "typebox"]} groupId="schema-validation" persist>

<Tab value="zod">

```ts title="@/lib/auth.ts" lineNumbers
import { createAuth } from "@aura-stack/auth"
import { identitySchema } from "@aura-stack/auth/identity/zod"
import type { UserFrom, SessionFrom, InferUser, InferSession } from "@aura-stack/auth/identity"

type _User = UserFrom<typeof identitySchema>
type _Session = SessionFrom<typeof identitySchema>

export const auth = createAuth({
  oauth: [],
  identity: {
    schema: identitySchema,
  },
})

export type User = InferUser<typeof auth>
export type Session = InferSession<typeof auth>
```

</Tab>

<Tab value="typebox">

<Callout type="warning">
  Aura Auth does not currently support inferring types directly from a TypeBox schema, due to the computational cost of TypeBox's
  type inference. As a workaround, use TypeBox's own `Static` type to derive `User` and `Session` from your schema manually.
</Callout>

```ts title="@/lib/auth.ts" lineNumbers
import { createAuth } from "@aura-stack/auth"
import { identitySchema, typebox } from "@aura-stack/auth/identity/typebox"

export type User = typebox.Static<typeof identitySchema>
export type Session = typebox.Static<typeof identitySchema>

export const auth = createAuth({
  oauth: [],
  identity: {
    schema: identitySchema,
  },
})
```
