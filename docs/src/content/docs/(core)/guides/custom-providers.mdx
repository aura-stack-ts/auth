---
title: Custom OAuth Providers
description: Define and configure custom OAuth 2.0 and OpenID Connect providers in Aura Auth.
---

Aura Auth supports integrations with providers that implement the [OAuth 2.0 Authorization Framework](https://datatracker.ietf.org/doc/html/rfc6749) and [OpenID Connect (OIDC)](https://openid.net/specs/openid-connect-core-1_0.html). These protocols allow applications to delegate authorization and authentication to external services and identity providers.

Aura Auth includes built-in providers for widely used services such as GitHub, GitLab, X, and Spotify. See the [OAuth Providers](/docs/oauth) guide for the complete list of supported providers.

When an application needs to integrate with an internal authorization server or a provider that is not included by default, Aura Auth supports custom provider configurations. These configurations allow the application to define provider-specific endpoints, scopes, and profile mapping while using Aura Auth's existing authentication flow.

## Adding a Custom OAuth Provider

A custom OAuth provider can be configured using the `OAuthProvider` type. The provider configuration defines the authorization and token endpoints, optional user information and token management endpoints, requested scopes, and profile mapping.

For the complete list of supported properties and their types, see the [OAuth Provider API Reference](/docs/api-reference/core#oauth).

### OAuth 2.0 Provider

The following table describes the main properties available when configuring a custom OAuth 2.0 provider.

| Property        | Type                                | Description                                                                            |
| --------------- | ----------------------------------- | -------------------------------------------------------------------------------------- |
| `id`            | `string`                            | Unique identifier for the provider within the application.                             |
| `name`          | `string`                            | Human-readable provider name.                                                          |
| `authorize`     | `string \| object`                  | Authorization endpoint URL or authorization endpoint configuration.                    |
| `accessToken`   | `string \| object`                  | Access token endpoint URL or token endpoint configuration.                             |
| `userInfo`      | `string \| object`                  | User information endpoint URL or configuration.                                        |
| `refreshToken`  | `string \| object`                  | Refresh token endpoint URL or configuration, when supported.                           |
| `revokeToken`   | `string \| object`                  | Token revocation endpoint URL or configuration, when supported.                        |
| `refreshWindow` | `number`                            | Time in seconds before access token expiration at which a refresh may be attempted.    |
| `scope`         | `string`                            | Scopes requested during authorization.                                                 |
| `profile`       | `(profile: Profile) => DefaultUser` | Optional function that maps the provider's profile to Aura Auth's user representation. |

```ts title="@/lib/auth.ts"
import type { User } from "@aura-stack/auth"
import type { OAuthProvider } from "@aura-stack/auth/types"

interface CustomProviderProfile {
  id: number
  username: string
  email: string
  name: string
  avatar_url: string
}

const provider: OAuthProvider<CustomProviderProfile, User> = {
  id: "custom",
  name: "Custom Provider",
  authorize: {
    url: "https://custom.com/authorization",
    params: {
      scope: "user:email user:profile",
      responseType: "code",
    },
  },
  accessToken: "https://custom.com/access_token",
  userInfo: "https://api.custom.com/v1/user",
  profile(profile) {
    return {
      sub: profile.id.toString(),
      name: profile.name,
      email: profile.email,
      image: profile.avatar_url,
    }
  },
}
```

The `profile` function maps the provider's profile to Aura Auth's user representation. The returned `sub` value must be a stable, unique identifier for the user within that provider. Avoid using mutable values, such as usernames or email addresses, as the subject identifier.

### OpenID Connect Provider

For providers that implement OpenID Connect, Aura Auth can use the issuer URL to configure the provider. OIDC defines an identity layer on top of OAuth 2.0 and standardizes identity claims and discovery metadata.

The following table describes the main properties available when configuring an OIDC provider.

| Property        | Type                                | Description                                                                            |
| --------------- | ----------------------------------- | -------------------------------------------------------------------------------------- |
| `id`            | `string`                            | Unique identifier for the provider within the application.                             |
| `name`          | `string`                            | Human-readable provider name.                                                          |
| `issuer`        | `string`                            | OpenID Connect issuer URL.                                                             |
| `refreshWindow` | `number`                            | Time in seconds before access token expiration at which a refresh may be attempted.    |
| `revokeToken`   | `string`                            | Token revocation endpoint URL, when supported.                                         |
| `scope`         | `string`                            | OIDC scopes requested during authorization.                                            |
| `profile`       | `(profile: Profile) => DefaultUser` | Optional function that maps the provider's profile to Aura Auth's user representation. |

```ts title="@/lib/auth.ts"
import type { User } from "@aura-stack/auth"
import type { OAuthProvider } from "@aura-stack/auth/types"

interface CustomOIDCProfile {
  sub: string
  name: string
  email: string
  picture?: string
}

const provider: OAuthProvider<CustomOIDCProfile, User> = {
  id: "custom-oidc",
  name: "Custom OIDC Provider",
  issuer: "https://custom.com",
  scope: "openid profile email",
  profile(profile) {
    return {
      sub: profile.sub,
      name: profile.name,
      email: profile.email,
      image: profile.picture,
    }
  },
}
```

For OIDC providers, the `sub` claim identifies the user within the issuer's namespace. Use this stable identifier to associate the authenticated identity with the correct user.
